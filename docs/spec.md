# 伊予鉄道 市内電車 乗換・時刻案内アプリ 仕様書

本書は実装の唯一の正（source of truth）である。本書に書かれていない仕様は推測で補わず、不明点は実装を止めて確認すること。

---

## 1. プロジェクト概要

### 1.1 目的
伊予鉄道 市内電車（路面電車）の利用者が、出発電停と到着電停を選ぶだけで、最短で乗れる電車の発車時刻・系統・所要時間を知れるようにする。時刻表や路線図が分かりにくいという課題を解決する。

### 1.2 対象路線
伊予鉄道 市内電車 全5系統（①②③⑤番、④は欠番、⑥番）。全29電停。郊外電車・バスは対象外。

### 1.3 配布形態
- GitHub / Vercel で一般公開予定。
- 個人＋友人向けだが公開物として品質を担保する。
- データは公式時刻表（2023年11月1日改正版）・路線図・運賃（2026年4月1日改定）を元に独自構造化した事実情報。READMEに出典・非公式・免責を明記する（公開時）。

## 2. スコープ

### 2.1 本リリース（Phase 1）に含む機能
1. 出発電停・到着電停の選択（あいまい検索対応）
2. 次発・次々発の表示（「次は約N分後」を含む）
3. 乗り換えなし経路の探索と複数経路比較（早い順に列挙）
4. 平日／土日祝（年末年始含む）の自動判定
5. 運賃表示（現金・IC両方）
6. 運行情報への外部リンク
7. 現在地から最寄り電停を提示（到着電停のみ指定でも出発を最寄りに自動設定）

本アプリの基本モードは「検索（出発・到着を指定して経路を得る）」であり、検索結果から同一OD・乗換なしの以降の便を時系列で一覧できる（経路の時刻一覧、5.3）。電停単体の全系統時刻表を丸ごと閲覧する機能は本リリースに含めない（Phase 2、2.2）。

### 2.2 本リリースに含まない機能（Phase 2 以降）
- PWA化（オフライン対応）
- 乗り換えあり経路の探索
- 電停別の全系統時刻表の閲覧（紙の時刻表の代替。中間電停が計算値のため精度誤解を避ける観点でも Phase 2 とする）
- 一日乗車券（1Dayチケット等）の損得案内
- 終電後の古町止め・特殊運用の詳細再現
- これらは実装しないが、データ・設計上の余地は残す（後述）。

### 2.3 UI・画面遷移について
本書では「アプリが備える機能」と「画面遷移の骨格」のみ定義する。具体的なUIの見た目・レイアウト・配色・コンポーネント配置は本書では規定しない。UI設計は別途 design.md および Claude Design の出力（ハンドオフバンドル）を基準とする。実装時、画面の見た目の最終的な正はハンドオフバンドルとする。

## 3. データ

### 3.1 データの所在と構造
データは `data/` ディレクトリに JSON で格納済み（本書に付随）。詳細は `data/README.md` 参照。

| ファイル | 役割 | 区分 |
|---|---|---|
| `stops.json` | 電停マスタ（29電停） | 一次 |
| `routes.json` | 系統定義 | 一次 |
| `timetable_route{1,2,3,5,6}.json` | 各系統の便ごと全電停時刻 | 一次 |
| `segments.json` | 中間電停の補間定義 | 派生（推定値） |

### 3.2 一次データと派生データの分離（重要）
- **一次データ**（timetable_route*.json の記載時刻、stops/routes）: 公式資料を元に構造化し、原本照合済み。変更しない。
- **派生データ**（segments.json）: 公式に時刻記載のない中間電停を補間する推定値。修正はこのファイルだけで完結させる。一次データを書き換えてはならない。

### 3.3 便ごとの全電停時刻モデル
各系統の時刻は「便（trip）」単位で持つ。各便は停車電停の発車時刻を `電停id: "H:MM"` で保持する。区間便（古町止め等）は通らない電停のキーを含めない。

### 3.4 日中便の展開
日中時間帯は公式PDF上「この間N分毎」と省略されている。各 timetable の `daytime_pattern` が以下を持つので、実装側で個別便を展開生成する:
- `first_departure` / `last_departure`: 展開する起点電停の発車時刻範囲
- `interval_min`: 運転間隔（①②=10分、③=12分、⑤=15分）
- `segment_offsets_from_origin`: 起点からの各電停の所要分
- 展開した便はすべて `saturday_holiday_suspended` がパターンの値に従う（日中の○分毎区間に運休便はない）。

### 3.5 中間電停時刻の算出（実行時計算）
時刻表に記載のない中間電停（高砂町・清水町・南町・道後公園・本町一/四/五など）の時刻は、静的に焼き込まず実行時に計算する:
- `前後の記載済み電停の時刻` ＋ `segments.json の区間内 offset`
- 中間電停の時刻は計算値であり目安である旨を、内部的に区別できるようにする（表示要件は6.2参照）。

### 3.6 曜日区分
- 平日ダイヤを基本とし、土日祝（および振替休日）に運休する便は `saturday_holiday_suspended: true`。
- ⑥番 本町線は全便が土日祝運休（`weekday_only: true`）。
- **年末年始（12/30〜1/3）は祝日扱い**とする。
- 確定済みの土日祝運休便（網掛け）:
  - ③番: 道後温泉7:27発、松山市駅7:51発
  - ⑤番: 道後温泉8:26発・8:37発、JR松山駅前7:51発・8:00発
  - ①②番: なし

### 3.7 運賃（2026年4月1日改定）
- 大人: 現金 250円 / IC・みきゃんアプリ 230円（キャッシュレス一律20円引き）
- 小児: 半額（10円未満切り上げ）。現金130円相当 / IC は小児10円引き。
- 市内電車は全線均一運賃（系統・距離によらず一律）。
- 運賃は固定値として持つ（データ化済みでなければ実装時に定数定義。出典: 2026/4/1改定）。

### 3.8 電停座標
`stops.json` の lat/lng は概算値で `requires_coord_verification: true`。現在地→最寄り電停判定に用いる。実装時、精度が必要なら実測値へ差し替える（座標の最終確定は実装フェーズの作業として許容）。

## 4. 主要データ型（モジュール0で確定する型の素案）

実装言語（TypeScript想定）での型の素案を示す。モジュール0で正式に確定すること。フィールド名はデータJSONに準拠する。

```
type StopId = string;            // 例: "dogo-onsen"
type TimeStr = string;           // "H:MM" 24時間表記、先頭ゼロなし（例 "6:05","21:30"）
type DayType = "weekday" | "saturday_holiday";

interface Stop {
  id: StopId;
  no: string;                    // 路線図上の電停番号 "01".."29"
  name: string;
  kana: string;
  romaji: string;
  aliases: string[];             // あいまい検索用
  lat: number;
  lng: number;
}

interface Route {
  id: string;                    // "1","2","3","5","6"
  name: string;
  color: string;                 // 系統色 HEX
  loop: boolean;                 // 環状線か
  weekdayOnly?: boolean;         // ⑥番のみ true
  // 方向別の電停順序（環状はstops_order、他はoutbound/inbound）
}

interface Trip {
  trip: string;                  // 便ID "E1","N3","O8" 等
  origin?: StopId;
  terminus?: "full" | StopId;    // 区間便の終点
  saturdayHolidaySuspended: boolean;
  stops: Record<StopId, TimeStr>;// 通過電停と発車時刻
}

interface DaytimePattern {
  origin: StopId;
  firstDeparture: TimeStr;
  lastDeparture: TimeStr;
  intervalMin: number;
  saturdayHolidaySuspended: boolean;
  segmentOffsetsFromOrigin: Record<StopId, number>;
}

// 経路探索の結果
interface RouteResult {
  routeId: string;               // 系統
  routeName: string;
  color: string;
  boardStop: StopId;             // 乗車電停
  alightStop: StopId;            // 降車電停
  departureTime: TimeStr;        // 乗車電停の発車時刻
  arrivalTime: TimeStr;          // 降車電停の到着時刻
  durationMin: number;           // 所要分
  isEstimated: boolean;          // 中間電停の計算値を含むか
  waitMin: number;               // 現在時刻からの待ち時間
}
```

## 5. ロジック仕様

### 5.1 曜日判定
- 現在日付（または利用者指定日）から平日／土日祝を判定する。
- 祝日判定には祝日ライブラリを用いる（7.2参照）。
- 12/30〜1/3 は祝日扱いに上書きする。
- 判定結果（DayType）で、運休便を除外する。

### 5.2 中間電停を含む全電停時刻の解決
- 任意の便について、記載済み電停はその時刻、中間電停は「直前の記載済み電停時刻 ＋ segments の offset」で解決する。
- daytime_pattern 由来の便は、origin の発車時刻 ＋ segment_offsets_from_origin で各電停時刻を解決する。

### 5.3 経路探索（乗り換えなし・複数経路）
入力: 出発電停 from、到着電停 to、基準時刻 now（既定は現在時刻）、DayType。
手順:
1. 全系統・全便（日中展開後・運休便除外後）を対象に、from と to の両方を通り、かつ from の発車時刻 ≧ now、かつ便の経路上で from が to より先に来る便を抽出する。
   - 環状線(①②)は loop。from→to の向きに走る系統（①時計回り／②反時計回り）が該当する。同一 from-to でも①と②で所要が異なりうるので、該当する両方を候補とする。
   - 道後温泉⇔大街道など複数系統が走る区間は、該当する全系統を候補とする。
2. 候補便を「to 到着時刻が早い順」でソートする。
3. 段階表示する:
   - **初期表示**: 直近で乗れる便を中心に3件程度を表示する。系統が異なる経路で到着が近いものがあれば、その中に含める（複数経路比較）。
   - **「もっと見る」**: 利用者の操作で、その日の以降の便を時系列で追加表示する（同一OD・乗換なしの全残便を順次見られる ＝ 経路の時刻一覧）。
   - 提示件数の初期値「3件程度」は機能要件。増やす操作のUI（ボタン/展開等）は規定せず design.md / Claude Design に委ねる。
- 乗り換えが必要な OD（本リリースでは乗換なし経路が存在しない場合）は「乗り換えが必要」である旨を案内し、Phase 2 対応とする（詳細探索はしない）。

### 5.4 次発・次々発
- 経路探索結果の上位2件以上を「次発」「次々発」として扱う。
- 待ち時間は「発車時刻 − now」を分で表示。中間電停では計算値のため幅を持たせた表現にする（6.2）。

### 5.5 現在地→最寄り電停
- ブラウザ Geolocation API で現在地を取得する（HTTPS前提、要許可）。
- 全電停との距離を Haversine 公式で計算し、近い順に提示する（徒歩圏の複数電停を出してよい）。
- 到着電停のみ指定された場合、出発電停を最寄り電停に自動設定する。
- 位置情報が拒否／取得失敗の場合のフォールバックは 5.6。

### 5.6 エッジケース（実装必須・推測で省略しない）
- **位置情報が拒否/利用不可**: エラーにせず、手動で出発電停を選べる状態にフォールバックする。最寄り提示機能のみ無効化し他機能は動作する。
- **終電後（その日の残便なし）**: 「本日の運行は終了」を示し、翌日始発を案内する（翌日が平日か土日祝かを判定して最初の便を出す）。
- **⑥番を土日祝に参照**: 全便運休のため経路候補から除外し、必要なら「本町線は土日祝運休」と示す。
- **同名電停（本町六丁目: 環状線09 と ⑥番終点29）**: 別電停として扱う。to/from 解決時に取り違えない。
- **出発＝到着が同一電停**: 経路を出さず、選び直しを促す。
- **古町止めなど区間便**: to がその便の terminus より先なら、その便は当該 OD の候補にしない。
- **始発前（その日最初の便より早い時刻）**: その日の始発を案内する。
- **中間電停発の便**: from が中間電停の場合も 5.2 で時刻解決して候補にする。

## 6. 表示・文言要件（UI見た目は規定しない／内容要件のみ）

### 6.1 必須表示要素
- 各経路: 系統番号と系統名、系統色、発車時刻、到着時刻、所要分、待ち時間。
- 運賃: 大人 現金/IC、（可能なら小児）。均一運賃である旨。
- 運行情報への外部リンク（6.3）。

### 6.1.1 系統の行先表示（方向幕表記・重要）
初めて乗る利用者が「画面の表示」と「目の前の電車の行先表示（方向幕）」を照合して迷わず乗れるよう、経路に出す系統表記は**実際の車両の行先表示に合わせる**。伊予鉄道も公式に「行先表示を確認して乗車」と案内している。
- **③⑤⑥番**: 「番号＋行先＋行」の形。例: 「③ 道後温泉行」「③ 松山市駅行」「⑤ JR松山駅前行」「⑥ 本町六丁目行」。
- **①②番（環状線）**: 行先が松山市駅に戻り「○○行」では向きが区別できないため、「環状線＋まわり方（経由地）」で示す。例: 「① 環状線 JR松山駅前まわり」「② 環状線 大街道まわり」。
- 系統番号の色（①緑②赤③橙⑤青⑥黒）は併せて表示する。
- 「行」は漢字表記とする。
- 補足: 内部の系統名（松山市駅線・JR松山駅前線・本町線・城南線等の正式線名）はデータ管理上は保持してよいが、利用者向けの主表示は上記の行先表示を優先する。

注: 本節により、これまで保留だった「系統名の表示文言（『城南線』等をどう見せるか）」を確定する。利用者向けは行先表示（番号＋行先＋行／環状線＋まわり方）を主とする。

### 6.1.2 経由駅の表示
利用者が「自分の降りる電停を通るか」を確認できるよう、経路の経由駅を見られるようにする。
- **次発（主役カード）**: 経由駅を表示する（乗車から降車までの通過電停。中間電停含む）。
- **一覧の各便**: 既定では経由駅を畳んでおき、タップ等の操作で個別に展開して経由駅を見られるようにする（全便を常時展開はしない＝情報過多を避け主役を妨げない）。
- 経由駅の見せ方（レイアウト）は design.md / Claude Design に委ねる。

### 6.1.3 現在時刻の表示
- 現在時刻を**秒単位**で表示する（利用者が「あと何分」の精度感を掴めるように）。
- 各便のカウントダウン（あと何分）は**分単位**でよい（秒で動かすと注意が散るため）。デモ用の基準時計がある場合はそれに同期する。

### 6.2 計算値（中間電停）の扱い
- 中間電停の時刻は目安である。待ち時間表示は「約N分後」等、幅・推定であることが伝わる表現にする。
- 記載済み電停（公式時刻）と中間電停（計算値）を内部で区別し、推定を断定的に見せない。

### 6.3 運行情報リンク
- 伊予鉄道の運行状況ページ（公式）への外部リンクを置く。URLは実装時に最新を確認する。

### 6.4 免責（公開時）
- 非公式である旨、時刻は目安であり正確性は公式を参照する旨を、READMEおよびアプリ内（ⓘ/About等の畳んだ場所）に明記する。
- 表記は「非公式」を基本とし、**制作者個人を特定し得る情報（個人制作である旨・居住地等）は記載しない**（プライバシー配慮）。
- アプリ内の免責はⓘアイコンや「このアプリについて」に畳み、主役（次発表示）を妨げない軽い扱いとする。常時表示する文言は「到着・所要は途中電停からの推定値です」程度に留める。
- 免責に含める情報: 伊予鉄道の非公式ツールである旨／時刻は目安で正確・最新は公式を確認する旨／データ基準（時刻：2023年11月1日改正、運賃：2026年4月1日改定）。

## 7. 技術スタックと制約

### 7.1 想定スタック
- Next.js（App Router）＋ TypeScript ＋ Tailwind CSS。
- データは `data/` の静的 JSON を読み込む（サーバー不要、クライアントサイドで完結）。
- ホスティング: Vercel。

### 7.2 使用パッケージ（追加が必要なもの。dev-guide の変更禁止事項に基づき、導入は明示確認の上で行う）
- 祝日判定ライブラリ（例: `@holiday-jp/holiday_jp` 等）。確定はモジュール0で。
- 上記以外の外部パッケージ追加・設定ファイル変更・ディレクトリ構成変更は、CLAUDE.md の「変更禁止（デフォルト）」に従い、明示許可を得てから行う。

### 7.3 やってはいけないこと
- 一次データ（timetable_route*.json）の時刻値の書き換え。
- 中間電停時刻の静的焼き込み（実行時計算で行う）。
- localStorage 等が必要な設計（本リリースは状態をメモリ保持で完結。永続化が要るならモジュール0で相談）。

## 8. モジュール一覧とロードマップ

dev-guide の規約に従い、先頭にモジュール0（共通規約・型定義）を置き、全体監査をデプロイ実行モジュールより前に配置する。

- **モジュール0: 共通規約・型定義の確定**
  - 命名規約、ディレクトリ規則、import/export方式、エラーハンドリング方針を `docs/conventions.md` に定義。
  - 第4章の型を `types.ts` として確定。データJSONのフィールド名と一致させる。
- **モジュール1: データ読み込み・正規化層**
  - `data/*.json` をロードし、型に沿って読み込む。電停・系統・便へのアクセサを提供。
- **モジュール2: 時刻解決ロジック**
  - 日中便の展開（daytime_pattern）、中間電停の補間（segments）、便ごと全電停時刻の解決（5.2）。
- **モジュール3: 曜日判定**
  - 平日/土日祝判定、年末年始の上書き、祝日ライブラリ統合（5.1）。
- **モジュール4: あいまい検索**
  - 電停名・かな・ローマ字・別名での検索（aliases 利用）。
